# План интеграции Gateway

## Реализуемая граница

Gateway предоставляет HTTP API Auth, Profile, Request/Core, Game и Chat,
проверку JWT и двух списков Redis, доверенные заголовки идентичности и роли,
CORS, журналы, тайм-ауты, health и readiness.
Источники поведения: [PROXY.md](PROXY.md) и [OpenAPI Gateway](contracts/gateway-openapi.yaml).

## Следующие проверки окружения

1. Настроить пять origin и пять реальных health URL по `.env.example`.
2. Проверить общий Redis и выдачу HS512 access JWT с `sub`, `jti`, `iat`, `exp`,
   `type=ACCESS` и ролью для операций модерации.
3. Выполнить сквозные сценарии регистрации, входа, refresh, выхода, бана и снятия
   бана, Profile, заявок, голосования, результатов, сообщений и отчётов Chat.
4. Проверить cookie Auth и запросы браузера с credentials через разрешённый CORS.
5. Подготовить образы сервисов и Compose, HTTPS и сетевую границу доверенных заголовков.

## Критерии приёмки

- Автоматические тесты Gateway и проверка актуальности OpenAPI проходят.
- Все пять сервисов доступны через Gateway по предоставленным контрактам.
- Найденный отзыв или бан блокирует запрос, а политика ошибок Redis соответствует PROXY.md.
- Прямой недоверенный доступ к сервисам не позволяет подделать заголовки Gateway.
- Readiness реагирует на отказ и восстановление каждой зависимости.

WebSocket, метрики, tracing и ограничение частоты запросов остаются отдельными задачами.
